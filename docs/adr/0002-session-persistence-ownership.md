# Guarded session persistence keeps the full-record shape

Every session save is a revision-checked compare-and-write of the complete Work Session record inside one IndexedDB readwrite transaction (`commitSession` in `src/db/history.ts`), with the storage revision stored on the record itself; Web Locks give the editing tab authority (`src/lib/sessionOwnership.ts`) and revision checks remain the correctness guarantee everywhere else. This rejects a split store of immutable PDF/image payloads plus a revision-checked manifest: a measured prototype of the existing record shape at the 500 MB source-byte ceiling (fake-indexeddb, Node vitest bench, 10-document sessions) showed revision-checked full-record update writes scaling linearly at ~28.5 ms (10 MB), 157.9 ms (50 MB), 333.4 ms (100 MB), 683.6 ms (200 MB) — 24× time for 20× bytes, extrapolating to roughly 1.7 s at the ceiling — with a 200 MB record read at 610 ms and heap staying flat near baseline (no 2× serialization spike), so full-record writes pass the latency gate for realistic sessions (autosave is debounced and off the interaction path), the memory gate, and do not trip the quota gate because total stored bytes are unchanged from the pre-R05 shape; payload splitting would only avoid rewriting unchanged bytes, which matters solely for the rare ceiling-sized session whose write bandwidth cost is bounded and asynchronous, so the migration complexity (atomic payload+manifest transactions, orphan cleanup, restore reassembly) is deferred, and if real-browser telemetry ever shows ceiling-sized sessions are common or disk I/O pushes saves past a few seconds, the recorded fallback is either the payload split or lowering the published `MAX_SESSION_BYTES` ceiling. Consequences: per-save write bandwidth rewrites unchanged payloads (accepted at measured rates), readers always get one coherent record from a single `get`/descending-index cursor, conflicts and refusals are explicit outcomes the lifecycle maps to visible states, and memory-only fallback mirrors the same revision semantics so guarded behavior never depends on durable storage being available.
