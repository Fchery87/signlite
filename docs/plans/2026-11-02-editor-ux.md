# Focused editor UX implementation plan

**Scope:** Improve the document editor and the signing tools it owns. Do not redesign intake, the queue, the global shell, local-data controls or PWA workflows.

**Goal:** Make precise PDF signing feel like a natural continuation of the warm-neutral queue, with a clear document hierarchy and less competition around the canvas.

## Direction

Retain warm paper `#F7F7F5`, ink `#1A1A18`, white tool surfaces, quiet borders `#E2E2DF`, warm selection `#EFEEE8`, and the existing system-font stack. Paper and the signature preview remain the primary visual objects, not decorative dashboard cards.

Separate the document identity and primary Download action from navigation. Use a compact page rail, flexible canvas and signing-tools panel on desktop. On smaller screens, Pages and Tools open the existing accessible dialogs and return users to the PDF after choosing a page or tool. Advanced repeated-placement and library maintenance actions remain available through disclosures rather than competing with normal signing.

## Implementation units

1. **Editor framing and feedback**
   - Files: `src/components/editor/EditorView.tsx`, `EditorPanel.tsx`, `ElementsPanel.tsx`.
   - Add previous/next page navigation with bounded targets and clear active-page status.
   - Move identity and Download to a dedicated document header.
   - Add concise start/review/download feedback without covering the document.
   - Offer retry on document-load failure without discarding work.
   - Preserve upload, shortcuts, export-policy disclosure, mutation locking and the session store's durable boundary.
2. **Page navigation**
   - File: `src/components/editor/PageThumbnails.tsx`.
   - Compact warm selection and stable preview framing, with `aria-current="page"`.
   - Preserve thumbnail scheduling and resource cleanup.
3. **Signing tools**
   - File: `src/components/library/LibraryTray.tsx`.
   - Clearly group saved signatures/initials and date/text tools.
   - Make preview click arm click-to-place and close the narrow-screen tools dialog.
   - Preserve explicit immediate Place and repeated-placement capabilities, asset creation, backup and management.
4. **Selected elements**
   - File: `src/components/editor/PlacedElement.tsx`, editor-scoped rules in `src/index.css` if needed.
   - Warm selection, grouped contextual actions and explicit deselect.
   - Preserve move/resize geometry, pointer ownership/cancellation, keyboard alternatives and text/export alignment.

## Verification

Write behavior tests first for navigation limits, start guidance, load retry, current-thumbnail semantics, tool arming and deselection. Run the editor, library, placement, shortcut and thumbnail tests, then the complete unit suite, typecheck, lint and production build. Exercise the built editor in desktop Chromium and Chromium/WebKit phone emulation, including draw/place/move/resize/edit/page-switch/download and narrow/landscape overflow. Review actual screenshots. Keep physical-device/stylus/OS-install claims outside this acceptance scope.

## Completion boundary

Changes are complete only after source review, regression evidence, a production browser check and a scoped commit. Update the canonical design reference only for verified shipped editor contracts. No production deployment or unrelated cleanup is included.
