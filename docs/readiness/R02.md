# R02 receipt. Export placements with the page's effective geometry

- Starting commit: `b232cfcc50131314d7f1869d8286d29f0a9a7e9f`
- Regression observed failing first: with the pre-change `flatten.ts` restored, the six new geometry tests fail (`maps a signature rectangle through the 90-degree rotated cropped geometry`, `maps text through the same geometry with a rotated baseline`, and all four `keeps the marker bounds and orientation at N degrees`); with the change applied, all pass.

## Changes

- `src/pdf/coords.ts`: `PageGeometry` (serializable width, height, rotation, scale-1 affine transform, effective view box, UserUnit), `pdfPointFromViewer` (inverse affine), `viewerRectToPdf` (full rectangle plus content rotation for right-angle pages). Not top-left-only: all four corners map, orientation derives from the transformed viewer x-axis.
- `src/lib/files.ts`: intake captures `pageGeometry` from the same scale-1 viewport the preview renders with, alongside `pageSizes`.
- `src/db/schema.ts`: `SessionDocument.pageGeometry?: PageGeometry[]`, documented as derived metadata that must agree with the immutable source bytes.
- `src/pdf/flatten.ts`: single export draws images and text through the inverse transform with a content rotation per page rotation; anchors are viewer bottom-left (image) and viewer top-plus-font-size baseline (text), matching preview conventions. Sizes divide by UserUnit because the transform already carries it. The old page-size-only path remains only for sessions whose geometry could not be reconstructed (see deviations).
- `src/pdf/render.ts`: `capturePageGeometry(pdf)` helper shared by intake and legacy reconstruction.
- `src/lib/normalizeSession.ts`: legacy sessions without geometry get it reconstructed from their source bytes in a `slice(0)` copy (stored bytes never detach); the probing document is destroyed in `finally`. When reconstruction fails on a placed document, the document enters needs-review with a specific reason instead of exporting misplaced marks.
- `src/lib/strings.ts`: `needsReviewPageGeometry` recovery message.

## Receipt-retention fix found during this task

Playwright deletes `test-results/` at the start of every run, which destroyed `test-results/readiness/` receipts (including R01's manifest) during ordinary suite runs. Receipt artifacts now write to `artifacts/readiness/` (gitignored, outside Playwright's output dir): `scripts/verify-production.mjs` and `pdf-output.spec.ts` updated; R01's manifest regenerated there from the current build.

## Deviations and decisions

- The page-size-only export path in `flatten.ts` is retained on purpose. It is not dead legacy: sessions whose geometry cannot be reconstructed from unreadable bytes still need a degraded fallback, and those documents are now flagged needs-review so the degradation is visible. No production caller of the obsolete conversion remains for documents with geometry.
- "Open representative outputs in a separate PDF viewer" is satisfied with poppler (an independent PDF implementation) rather than a GUI viewer; no desktop viewer is available in this environment. Measured, not inferred.
- Asymmetric-image orientation evidence comes from the typed signature's 596x142 non-square PNG with an off-center drop point, which caught axis swaps.
