# R05 receipt. Guard persisted writes and history deletion

- Starting commit: `4723fbc` (R04)
- Regression observed failing first: with `sessionLifecycle.ts`, `sessionOwnership.ts`, `sessionOwnership` deps in `useSessionLifecycle.ts`, `db/history.ts`, `db/schema.ts`, `normalizeSession.ts`, `App.tsx`, and `strings.ts` stashed (new tests kept), 36 of 44 guard-area unit tests fail (guarded repository contracts, ownership acquisition/contention, create-vs-update semantics, refusal handling) and the new `multi-tab.spec.ts` e2e fails (no `read-only-banner`; the red e2e build used `vite build` alone because typecheck fails under the stash). With the change applied, all pass.

## Changes

- `src/db/schema.ts`: `WorkSession.storageRevision?: number` persisted on the record; `MIN_COMPATIBLE_DB_VERSION = 1` with `blocked`, `blocking` (old connection closes itself so another tab's upgrade proceeds), and `terminated` (dead handle dropped, next open re-establishes) connection callbacks. An outdated bundle's `VersionError` is distinguished from a missing/failed open.
- `src/db/history.ts`: guarded repository behind explicit outcomes.
  - `commitSession(session, expected)` compares and writes the storage revision inside one readwrite transaction. `mode: 'create'` writes only when the id is absent; `mode: 'update'` requires the expected revision (legacy revision-0 records upgrade legitimately; an update against a deleted record is refused, never recreated). Returns `saved` with the next revision, `conflict` (`exists` | `missing` | `changed`), `memory-only`, or `refused` (`version`).
  - `loadSession(id)` / `loadLatestSession()` return the session with its base storage revision; `loadLatestSession` reads only the newest complete record via a descending `by-updated-at` cursor instead of cloning every record.
  - `deleteIfUnchanged(id, expectedRevision)` returns `deleted` | `changed` | `missing`; `pruneOldSessions(cutoff, withLock?)` runs each victim deletion under the session lock when one is provided and skips deletions when locks are unavailable.
  - Version-refused databases never start a memory-only writer; the memory fallback mirrors the same revision semantics on quota failure.
- `src/lib/sessionOwnership.ts` (new leaf module): `sessionLockName(id)`, `acquireSessionOwnership(id)` (nonblocking; the held promise resolves on release so the tab owns the lock for its lifetime), and `withSessionLock` for prune/delete serialization. Outcomes: `owned` | `contended` | `unavailable`.
- `src/lib/sessionLifecycle.ts`:
  - `DurabilityState` gains `authority: 'owner' | 'read-only' | 'optimistic'` (default `optimistic` so pre-ownership behavior is unchanged until an assumption is made).
  - `assumeSession(id)` cancels any pending save and bumps the generation before awaiting the lock (stale queued writes die), releases the prior lock, acquires the new one, sets authority, resets suppression, and re-processes the buffered observation under the settled authority so a save skipped during identity transition is not lost. The debounce callback re-checks authority and identity alignment at fire time (a resumed session can turn read-only during the 500 ms window; a never-assumed identity is only written once ownership tracking is active).
  - `persist` builds a `CommitExpectation` from the base revision tracked per session id (`baseRevisionFor`); create semantics on first save of a fresh id, update semantics after load. Saved results advance the base revision even while a newer revision remains dirty, so the queued newer snapshot commits against the returned token without self-conflict. Conflicts and refusals set `suppressed` with visible copy ("changed in another tab" / "refresh"); recovery is an explicit `assumeSession` for a fresh id. Read-only tabs neither save nor mark dirty.
  - Explicit clearing uses `deleteIfUnchanged`; a queued empty clear still precedes a newer nonempty save (no resurrection), while `completeRevision` stays generation-guarded.
  - `startupAndDiscover` passes a `withLock` built on `withSessionLock` to pruning; unavailable locks skip all automatic deletions.
  - `startFresh` keeps the predecessor (no eager deletion, no localStorage marker); retention is revision-guarded.
- `src/lib/useSessionLifecycle.ts`: effect keyed on `[lifecycle, session.id]` calls `lifecycle.assumeSession(session.id)`, so resume and Start Fresh both re-establish authority.
- `src/lib/normalizeSession.ts`: no longer stamps `updatedAt: Date.now()`; stored `updatedAt` and `storageRevision` survive normalization (a restore no longer fabricates freshness or drops revision metadata).
- `src/App.tsx` (deviation, see below): renders `data-testid="read-only-banner"` with `STRINGS.readOnly` beside the durability status when `authority === 'read-only'`.
- `src/lib/strings.ts`: `readOnly: 'Another tab is editing this Work Session. This view is read-only.'`
- Tests: `tests/unit/history.test.ts` (guarded repository: two-writer literal A/B refusal, legacy revision-0 update, delete-only-if-unchanged, newest-record cursor read), `tests/unit/history-guard-memory.test.ts` (memory fallback revision semantics; version refusal never enables memory writes), `tests/unit/history-open-fallback.test.ts` (blocked/blocking/terminated connection handling), `tests/unit/session-ownership.test.ts` (acquire/contend/unavailable, release semantics), `tests/unit/session-lifecycle.test.ts` (create-vs-update expectations, token advancement with newer-dirty content, conflict suppression and recovery, refused→refresh copy, contended→read-only with no writes, unavailable→optimistic, ownership release on id change, no predecessor marker/eager delete), `tests/unit/use-session-lifecycle.test.tsx` (assumeSession per id including after Start Fresh, no re-assume on plain edits), `tests/unit/normalize-session.test.ts` (+2: `updatedAt` and `storageRevision` preserved), `tests/e2e/multi-tab.spec.ts` (new: owner edits and saves, second tab resumes read-only with visible banner, owner keeps saving through the observer's session).

## Deviations

- `src/App.tsx` and `src/lib/strings.ts` appear in the change list beyond the plan's named files: the acceptance state "second tab sees a visible read-only banner" needs a rendered element, so the banner lives next to the durability status using the existing `warning` palette token (no `attention` color exists).
- `pruneOldSessions` takes `withLock?: (id, operation) => Promise<boolean>` rather than a lock-manager object: the lifecycle already owns lock acquisition, so the hook injects its adapter and history stays storage-only.
- `src/lib/sessionOwnership.ts` was created (the plan anticipated this with "if ownership needs a separate module"): it keeps `navigator.locks` handling out of the React hook and out of history.
- The "refuse destructive clearing when locks are unavailable" item maps onto existing surfaces rather than new UI: retention pruning skips every deletion when locks are unavailable, the empty-session clear is revision-guarded to the tab's own record, and no explicit user-facing session-deletion control exists (Start Fresh preserves the predecessor by design); recovery export is the app's existing download flow and does not depend on locks. The legacy blind writers (`saveSession`, `clearSession`) have no production callers and are marked test-only fixtures.

## Measured prototype (ADR 0002)

No database-version bump shipped: the ADR decided against payload splitting, so the store shape is unchanged at `MIN_COMPATIBLE_DB_VERSION = 1`; the connection lifecycle handlers (blocked/blocking/terminated) and the version-refusal path implement the item's protection without new stores. Old bundles meeting a future upgraded store stop and request refresh via `VersionError` → `refused`.

Full-record revision-checked writes at the byte ceiling were measured before deciding against payload migration (fake-indexeddb bench, 10-doc sessions): update writes 28.5 ms at 10 MB, 157.9 ms at 50 MB, 333.4 ms at 100 MB, 683.6 ms at 200 MB (linear, ~1.7 s extrapolated at the 500 MB ceiling), 200 MB read at 610 ms, heap flat. Decision and gates recorded in `docs/adr/0002-session-persistence-ownership.md`.
