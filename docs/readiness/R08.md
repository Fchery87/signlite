# R08 receipt. Use one text layout for preview and export

- Starting commit: `c14c5fb` (R07)
- Regression observed failing first: `tests/e2e/text-output.spec.ts` did not exist; the first red run against the freshly built bundle failed 4 of 5 scenarios (Greek/Cyrillic download never completed, the unsupported-character message was absent, exports differed across zoom, and truncation did not truncate). `tests/unit/text-layout.test.ts` red state included the wrap-point space loss (`brownfox`) and the unbroken long first word before the fixes landed.

## Font decision

Bundled **DejaVu Sans** (regular), unmodified, from the distribution package whose upstream is dejavu-fonts.github.io.

- Coverage: 100% of Basic Latin, Latin-1, Latin Extended-A/B, Greek and Coptic, and Cyrillic per the package's own Unicode coverage report. This matches the plan's declared script set; CJK and most emoji are outside it and are refused explicitly.
- License: Bitstream Vera permission text plus public-domain DejaVu changes. Redistribution inside a larger software package is permitted with the notices retained; the font ships verbatim, so no rename obligation applies. The verbatim license file ships at `src/pdf/fonts/DejaVuSans-LICENSE.txt` and in the served artifact at `public/fonts/DejaVuSans-LICENSE.txt`. The project's own license choice remains R12's owner decision; nothing here invents a grant.

## Architecture

- `src/pdf/textLayout.ts` is the single text model. It measures with the font's own metrics (fontkit `layout` advance widths), wraps with `pre-wrap` semantics (explicit newlines break, interior spaces preserved, wrap points drop the pending space), breaks over-long words at the box edge, computes the CSS line-box baseline (half-leading plus ascent) so the exported baseline lands on the preview's, and truncates lines that would run past the box bottom.
- The preview (`PlacedTextBody` in `PlacedElement.tsx`) renders exactly those lines as explicit line boxes in the bundled face, registered from the same bytes via `FontFace`. The export (`flatten.ts`) embeds the same bytes through pdf-lib's fontkit integration, subsetted, and draws the same lines with the same per-line baselines.
- Font bytes ship as a generated base64 module (`scripts/generate-font-module.mjs` → `src/pdf/generated/embeddedFontData.ts`, committed) rather than a runtime URL. The app's CSP forbids fetches, so a fetched font would break the R09 readiness contract; both consumers read the same module, which is what makes one layout real.
- Imports in `textLayout.ts` are static. The dynamic-import version hung every test that runs under `vi.useFakeTimers`, because the module load never resolves under fake timers; static imports also mean no runtime module loading, which R09 wants anyway.
- `resolvedAt` flows from one instant per export attempt: the single download captures it before the preflight, and the batch runner puts it in the worker request so every document in a batch shares one date across a midnight.

## Unsupported scripts

`findUnsupportedCharacters` reports characters whose codepoint has no glyph (glyph id 0) — measured: CJK and `🎉` report; `😀` reports as covered because the font genuinely carries it. `assertTextExportable` runs in both entry points before any document is opened for writing, because `flattenDocument`'s catch masks every error with the generic recovery copy. The refusal names the characters; the placement stays editable. This satisfies the plan's requirement that the Chinese fixture produce the explicit unsupported-script result.

## Defects found and fixed on the way

- **`customName` silently disables pdf-lib subsetting.** Passing `{ subset: true, customName }` produced 483 KB output; dropping `customName` produced 5.6 KB for the same document. The only evidence was the byte count.
- **The export bottom-aligned letterboxed images.** The preview centers the aspect-preserving inner rect (`object-contain`); the export anchored the drawn image's bottom at the box bottom. Identical when the box aspect matched the image, off by exactly (boxH − drawH)/2 the moment it did not — 3.9 pt in the browser proof, against a 1 pt contract. Fixed to center on both axes; all four right-angle rotation unit pins still hold because their fixtures square off.
- **The placement border inset the preview content.** A 1px border on the placement button shrank the visible marker ~2px, which flipped object-contain's limiting axis and made the preview disagree with a correct export. The border is now an overlay on top of the content.
- **The wrap point lost its space and a long first word never broke** — both caught by the layout unit tests before any browser run.
- **My own first hand-derived baseline expectation was wrong twice.** The rotated-baseline pin I computed (97.3543, 32) was off; the emitted value (127.3543, 62) is what the inverse transform actually produces. The pin now records the derivation.

## Test-infrastructure changes

- `tests/e2e/text-output.spec.ts` (new): Latin plus newline extraction, Greek/Cyrillic extraction, the unsupported-character refusal (and that no download fires), zoom invariance via extracted-text equality, and truncation of lines past the box bottom.
- `tests/e2e/pdf-output.spec.ts`: now measures the visible marker (contain math on the real image) instead of the wrapper box, and waits for the placed box to settle before measuring. The R02 contract — export matches preview within 1 pt at Fit/100%/150% and DPR 2 — passes against the new letterbox semantics.
- `tests/e2e/batch-flow.spec.ts`: the sentinel assertion read content-stream hex, which only worked because WinAnsi codes happen to look like ASCII. It now extracts text with pdf.js, the same library the app renders with.
- `tests/unit/editor-view.test.tsx` and `tests/unit/editor-shortcut-scope.test.tsx` mock `textLayout`; those tests cover placement behavior, not typography.

## Deviations

- Text and date placements now visibly render in DejaVu Sans in the preview rather than the app's UI font. This is the price of one shared layout: the preview must draw the face the export embeds.
- Overflow policy is truncation at the box, on both sides. The plan requires that long text cannot cover an adjacent field; dropping the lines that do not fit is the simplest policy both sides can implement identically. A user who needs more room resizes the box.
- Full PNG integrity is not verified on import (R06 note that also applies here): the signature path validates structure, not pixels.

## Not verified here

The font's license compliance rests on the distribution package's own license and coverage files shipped alongside the binary; I did not re-verify the upstream release independently. The 24 ms subset-embed figure is a jsdom measurement, not the recorded target hardware R13 will use. Preview and export share the same shaping engine for wrapping, but the browser's rasterizer and pdf-lib's glyph placement can still differ by sub-pixel amounts inside the 1 pt tolerance; the agreement is verified, not proven.
