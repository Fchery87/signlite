- Starting commit: `c84a434ec1e0f66160683019276a91da9c059399`

## Changes

- `src/components/editor/PlacementLayer.tsx`: `dragover` gates on `dataTransfer.types.includes(ASSET_DRAG_TYPE)` only; the payload is read once in `drop`. `parseDragAsset` requires finite positive dimensions and a known id before placement. Invalid payloads toast `STRINGS.editor.invalidDropPayload`.
- `src/lib/sessionLimits.ts` (new): the four session ceilings (`MAX_FILE_SIZE`, `MAX_SESSION_FILES`, `MAX_SESSION_PAGES`, `MAX_SESSION_BYTES`) and `SessionResourceBudget` live in a leaf module so both the domain and intake validation read the same numbers. A dedicated leaf keeps the architecture boundary intact: only `src/stores/session.ts` may reference `workSessionEditor` (enforced by `tests/unit/architecture-boundary.test.ts`).
- `src/lib/workSessionEditor.ts`: `addDocuments` computes the combined budget (documents, pages, source bytes) and rejects with reason `session-limit-exceeded` before mutating state.
- `src/lib/files.ts`: re-exports the ceilings and budget type from `sessionLimits.ts`; validation behavior unchanged.
- `src/stores/session.ts`: `addDocuments(docs, expectedSessionId?)` now returns a typed outcome `'ok' | 'lease' | 'session-changed' | 'budget'` instead of `void`. A session under a mutation lease returns `'lease'`; a result prepared for a different session id returns `'session-changed'` and mutates nothing; a budget overflow returns `'budget'`.
- `src/components/DropZone.tsx`: rejection copy moved into an exhaustive `Record<FileValidationError, (fileName) => string>` registry, so a new validation variant without copy is a compile error. Intake runs serialize through a ref-held promise queue; each queued run reads budgets from a render-updated ref, so it commits against what earlier runs produced, not drop-time props. The session id is captured when the drop starts; the store outcome is checked after commit and non-`ok` outcomes toast specific copy rather than losing the result silently.
- `src/App.tsx`: passes `sessionId={session.id}` and the outcome-returning `addDocuments` to DropZone.
- `src/lib/strings.ts`: `invalidDropPayload`, `intake-lease-refused`, `intake-session-changed`, `intake-budget-refused`.
- Tests: `tests/unit/placement-layer.test.tsx` (native-drag gate, malformed payload), `tests/unit/dropzone.test.tsx` (51st document refused pre-parse with `createSessionDocument` uncalled, mixed batch per-file reporting, store refusal toast, overlapping intake queue), `tests/unit/store.test.ts` (budget, session-changed, lease refusals at the store boundary), `tests/e2e/sign-flow.spec.ts` (library-card `dragTo` with persisted placement), `tests/e2e/intake-limits.spec.ts` (new: 51st document, mixed batch, non-PDF native drop never navigates away).

## Deviations and decisions

- Ceilings live in `src/lib/sessionLimits.ts` rather than inside `workSessionEditor.ts` as the plan's file list implied. The architecture boundary test forbids any file but the store adapter from referencing `workSessionEditor`, so importing the constants from there would fail the boundary. The leaf module keeps one source of truth; enforcement still lives in the domain.
- Zoom and scroll interaction with native dragging is covered by construction (placement math uses `getBoundingClientRect`, which is scroll-aware) and by the existing zoom suite, not by a dedicated zoomed-drag e2e. Inferred safe; not separately measured.
- The e2e mixed-batch and navigation tests also pass against the pre-change code; they are behavior-preservation tests, not regression discriminators. The discriminators are listed in the regression note above.
- The old per-file toast copy is preserved (file-name prefixes where tests asserted them); the DropZone list items now show the same per-file strings, which is a small visible copy change on rejected-file rows.
